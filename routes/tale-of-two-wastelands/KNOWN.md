# tale-of-two-wastelands: what we know about driving it

Read before every launch. Add what you learn the same session (`known FOLDER --add ...`).
Only game facts: no paths, machine names or people.

## Menus

- 2026-11-09: Main menu: Continue / New / Load / Settings / Credits / Quit on the right; TTW's own self-check shows boxes here when a requirement is missing (ShowOff, JohnnyGuitar, falloutcustom.ini).
- 2026-11-19: the main menu's background is the file textures/interface/main/main_background.dds (1920 x 1080; a 16:9 picture is stretched sideways on a 21:9 screen) and its music is Music/Special/MainTitle.mp3; the highest mod in the list that carries each one wins. The menu overhaul (MAPMO) sets the menu music volume itself (fMainTitleMusicSound in its config), over fMainMenuMusicVolume in the INI: a silent MainTitle.mp3 is what keeps the menu quiet. Quit on the main menu closes the game at once, no question.

## Controls

- 2026-11-10: 2026-11-10: in VR with the pretend hands (VR Bench layer, 32-bit): Y opens the pause menu, B closes it; on the main menu A presses the highlighted Continue. With Stewie's Tweaks setting bAutoContinueGame = 1 (our own override file in a desk-test mod) the newest save loads from the start menu with no press at all.
- 2026-11-12: in VR with the pretend hands: Activate (a door, an item) is the A button on the hand that points at it, and it has to be HELD about one second; a short tap only shows the prompt. The walk stick (left, forward) and the turn stick (right) work as on a real controller.
- 2026-11-13: 2026-11-13: the console opens with the grave/tilde key (scancode 0x29) once a save has loaded; typed with SendInput scancodes at ~0.1 s per key it works (faster drops keys). player.moveto SpringvaleElementaryMapMarker puts the player outside Springvale school. Windows may refuse to bring the game to the front: an Alt tap first, then SetForegroundWindow (tools/console_type.py in the bridge repo).
- 2026-11-19: console commands that work typed into the VR game on the simulator: `tll` hides the far land AND the far water, `tws` hides all water, `set gamehour to 4` + `set timescale to 120` runs a dawn in about two minutes (put the timescale back to 30). With the pretend head tilted up 35 degrees the upper half of the eye picture is sky.
- 2026-11-19: flat main menu, keyboard by SendInput scancodes: Down moves the highlight (the first Down lights Continue; six Downs reach Quit) and Enter HELD about 0.12 s selects it. The quick Enter tap of 2026-11-09 was too short. Look at the highlight before Enter: New sits two rows under Continue.
- 2026-11-19 (later): on the Load page of the flat main menu neither Esc nor Tab (SendInput scancodes) goes back, with the list's stock menu layout as well (n=1 each); the mouse on BACK does. On the Load page Enter LOADS the lit save: never press Enter after an Esc without a look (done once by mistake; the game was closed at once, nothing was saved).
- 2026-11-20: the borderless-window add-on (OneTweak, window and render size on autodetect) stretches the flat game over the whole screen whatever iSize W / iSize H say: on a 21:9 screen a 16:9 menu picture comes out stretched. For a true 16:9 window set WindowWidth/Height and RenderWidth/Height (and WindowPosX/Y) in OneTweak.ini with the game closed, iSize the same; put both back after. `[verified-live 2026-11-20, n=1]`
- 2026-11-20: the main menu draws the game's own mouse arrow in the middle of the screen and reads the mouse as relative moves: about 40 relative moves of 120,120 (SendInput, game in front) park it in the bottom-right corner, out of a picture, and light no menu word. Six Downs then held Enter still quits afterwards (n=2).
- 2026-11-20: after a desk run on the OpenXR Simulator left running (--stay), switching the VR Bench hands off makes the game show 'The Xbox 360 Controller has been disconnected ... Ok'; the game does not close behind it (a polite close waited over 2 minutes). Enter (its only button) and it closes in seconds. `[verified-live, n=1]`
- 2026-11-20: the flat game's Print Screen picture goes where SScreenShotBaseName ([Display], Fallout.ini and FalloutPrefs.ini of the profile) points; a full path with a folder works (the folder must exist). The counter iScreenShotIndex is per profile, so give each profile its own name in the base name, or two profiles overwrite each other's numbers in one folder. `[verified-live, n=1]`
- 2026-11-20: Save 4 does not always load to the same view in flat desk runs when someone moves the mouse during the run; with nobody touching the mouse it did, run after run (n=6). A desk check that compares pictures should find the view's shift first.
- 2026-11-20: the idle third-person 'vanity' camera that swings round after standing still is switched off by bDisableAutoVanityMode=1 in [General] of the profile's Fallout.ini (the name is in the game program; not in Stewie's Tweaks). Checked over a 6-minute run standing still: first person throughout. `[verified-live, n=1]`
- 2026-11-20: a clean 24-hour timelapse from one spot: console tgm, tcai, set timescale to 240 (one game day in 6 minutes), then tm (HUD off, typed last so the console is shut); afterwards tm and set timescale to 30, and do not save. A named save first (save <name>) gives the second run the same spot and hour.
- 2026-11-20: `set timescale to 1` from the console crashes this list a few seconds later (Stewie's Tweaks' low-actor update, the same call trace twice); 240 and 30 are fine. `[verified-live, n=2]`
- 2026-11-20: when the game crashes while console lines are being typed, keys sent with SendInput go to whatever window comes to the front: check the game is in front before EVERY key (console_type.py does since).
- 2026-11-20: JIP script-runner files (Data/NVSE/Plugins/Scripts/ln_*.txt, every load and new game): a variable named like an existing form ('rC') stops the whole file ('Form with that Editor ID already exists', in nvse.log); an inline function in brackets is capped at 512 characters, so longer ones go in Data/NVSE/user_defined_functions/<folder>/<name>.gek and are registered with SetGameMainLoopCallback (CompileScript "<folder>\<name>.gek") 1 30 1. GetClimateTraitNumeric <climate> 0..3 gives sunrise begin/end and sunset begin/end in MINUTES (5:00 = 300).

## Save spot

- 2026-11-12: the rung-1 test save stands inside Springvale Elementary School beside its double door, which is on the left (90 degrees). Pointing the right hand at it and holding A for a second loads the Capital Wasteland outside in about 10 s. The game writes an autosave on the way: put the save folder back after a run (the desk check does it by itself with --outside).
- 2026-11-13: 2026-11-13: the auto-load (Stewie's bAutoContinueGame) takes the NEWEST save; a person's own later save then wins. Desk runs must make the test save newest for the run and put its date back (rung_simcheck --save).
- 2026-11-19: 'Save 4' (The Capital Wasteland, on the rock above the lake) is the look-out for picture faults: the water is at about x 150-510, y 280-360 of the simulator's 569x604 left-eye picture with the head straight. A desk run left running (`--stay`) keeps the test save's date bumped: put it back afterwards (the file's creation date is the real one).

## Hazards

- 2026-11-10: 2026-11-10: never name this game's window to a tool by the word 'Fallout' alone: a chat program open on a thread titled 'Fallout 3/NV VR ...' matched first, a picture of IT was taken and the quit keys were nearly typed into it (nothing was sent). The game's window belongs to FalloutNV.exe; check the program behind a window before using it. While an add-on has a box up, the game's main window is that box (title 'New Vegas Tick Fix', 'Stewie Tweaks', 'Fatal Error: Missing NVSE Plugin').
- 2026-11-10: 2026-11-10 (later): from Lanes 0.106.2 every Menu-o-matiC / Move-o-matiC / State-o-matiC command takes --exe FalloutNV.exe (and a route file may carry "exe"); with it a window of another program is refused. Every route recorded for this game must carry it. The home PC has 0.106.2 since 2026-11-10 (after a restart of the session); not yet run against the real game.
- 2026-11-10: 2026-11-10: the game opens its pause menu when its window is not in front (the OpenXR Simulator's window takes the front); bNoAltTabPause = 1 and bNoPipboyOnAltTab = 1 in Stewie's Tweaks stop that. Never start the next run before the last FalloutNV.exe has gone: two copies ran once and neither answered a polite close for over a minute.
- 2026-11-12: after a polite close the game can take over a minute to go; wait until no FalloutNV.exe and no Mod Organizer is left before the next start. One start in nine today crashed 5 s in (rung 5, an error in the C runtime) and passed on the next try.
- 2026-11-13: 2026-11-13: in an OpenXR Simulator run the simulator reads W/A/S/D/Q/E/I/J/K/L (and its own view keys) off the keyboard while the game's window is in front (input_polling 'app'): typing into the game's console moved the pretend head and changed the preview. Set input_polling to 'preview' in the simulator's settings.json (game closed) for a run that types, and back after. The simulator's preview window is in the game's own program: check the WINDOW, not only the program, before typing.
- 2026-11-13: 2026-11-13: after a crashed start Steam's overlay starter (x64launcher.exe) can stay up with no window; Mod Organizer then never closes and the next run never starts. Only /F ends it (harmless once the game is gone).
- 2026-11-19: the VR mod re-writes 33 graphics settings into the game every frame (water reflections, ripples and depth haze off among them), so setting them from the console or the INI does nothing.
- 2026-11-19: the leftmost ~40 pixels of the simulator's eye picture show a stale strip of an older frame: crop it off before measuring anything.
- 2026-11-19: the game's lists cut off whatever hangs outside their box (clipwindow): a font whose letters sit lower in the row loses the bottom of the last word. A font's two placing numbers in its .fnt (the line height at the start and each letter's 'top above the line') move a line of text up when raised.

## What failed

- 2026-11-09: 2026-11-09, main menu (Begin Again debug profile, OneTweak borderless 3440x1440): a Menu-o-matiC click does not move the game's own cursor; Down (SendInput) moves the highlight; Enter and E (SendInput) do NOT select. Untried: key_input post/both, a held key, the mouse moved over the item then clicked.
- 2026-11-10: 2026-11-10: the main menu ignores a WM_CLOSE to its window. A polite 'taskkill /IM FalloutNV.exe' (no /F) closes it.
- 2026-11-10: 2026-11-10: in the OpenXR Simulator the VR mod (TTWVR 1.0.0) shows its menus but never refreshes the 3D world: after a save loads the picture stays on the save's frame or black, and head, sticks and hands change nothing. Upscaler off, smaller eye size, game window in front, Continue by hand: no change. The headset run's log has a '[camtrack] ... the body is solved from the headset and the controllers' line that never appears in the simulator.
- 2026-11-11: a polite 'taskkill /IM FalloutNV.exe' also sends the close message to the OpenXR Simulator's preview window (it lives in the game's process): the simulator stops the session, the VR mod logs 'the headset's session is gone' and connects again, and the game can take 40 s more to close. Measure everything before asking the game to close.
- 2026-11-11: in the simulator the VR mod's pictures follow the head but are black in the world. Suspect: Virtual Desktop's body memory (VirtualDesktop.BodyState) exists, empty, whenever the Virtual Desktop Streamer runs, and the mod then skips its own body solver. Not yet tested with the Streamer quit.
- 2026-11-12: the frozen 3D world of 2026-11-10 / 11 in the OpenXR Simulator is explained and stepped around. With DLSS on, the VR mod has its helper program draw each eye straight into the headset runtime's own pictures through an old-style shared handle; the simulator's pictures are plain, so the mod silently repeated the previous picture. Our own desk-test add-on makes those pictures shareable (old kind, flag 0x2; the newer kind 0x802 does not work) and also answers "no Virtual Desktop body memory", so the Virtual Desktop Streamer may keep running. With it the eye is live at 90 a second.
- 2026-11-13: 2026-11-13: TTWVR 1.0.0's command file NVVR-cmd.txt beside TTWVR.log (direct write and rename) was never taken by the running game in the simulator, n=2, though the DLL has the code.
- 2026-11-19: Enter on the flat main menu worked on every fresh start with the game in front all along, and failed several times after the game's window had lost the front to another window and got it back (arrows still worked) `[hypothesis: the focus change, not tested apart]`. The polite close request is the fallback.
